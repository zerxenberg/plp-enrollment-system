## Approved scope

- The project is for coursework and demonstration by a small developer group. Preserve the existing Student, Registrar, Academic Coordinator and System Administrator workflows and original 2,128 inactive planning records.
- For schema safety, check existing `public` tables actually used by the PLP application, the new project tables and the only approved PLP migration creator: non-superuser `current_user=session_user=postgres`.
- Continue requiring zero effective `TRUNCATE` privileges for `anon` and `authenticated` **on existing PLP public tables**, RLS enabled, matching table owners, proper constraints and foreign keys, and no unsupported client role membership or `CREATE` privileges.
- For new PLP tables, require secure **creator-specific** public/global default privileges under `postgres`; create new objects with explicit grants and protective RLS in reviewed transactions. Do **not** require zero privileges for future objects of unrelated system-managed table creators as a PROJECT_ONLY release criterion. The activation readiness query and physical trigger must use the same scoped criteria.
- No users may receive broader enrollment/academic authority by virtue of test student or administrator identity. Preserve the real student-self access checks, read-only authoritative academic data, admission handoff rules, and Registrar final enrollment authority.
- Independent release requirements remain: verified Auth no-email behavior, securely stored unique credentials and mandatory first-login password change, individual System Administrator authorization and audit, exact 600 fictional profiles linked 1:1 to Auth, four-role access tests, preservation of 2,128 original inactive accounts, rollback-aware migration deployment and final data-integrity tests.
